# Fix WiFi Unavailable After Rebase (iwd Masked)

## Context
After rebasing to the custom image (`ghcr.io/herb/bazzite-vm-rocm-niri:20260514`) built on `ghcr.io/ublue-os/bazzite:stable`, the WiFi adapter (MediaTek MT7925) was no longer able to see or connect to any networks. The previous image (`bazzite-dx:stable`) had working WiFi. Rolling back restored connectivity.

## Alternatives Considered
1. **Switch base to `bazzite-dx:stable`** — Would use standard Fedora kernel (`6.17.7-ba29.fc43`) with Fedora-signed modules. Rejected because the goal is kernel >= 6.19 for VM and ROCm compatibility.
2. **Enroll OGC kernel MOK key** — The OGC kernel modules are signed by a `Build time autogenerated kernel key`. Required enrolling the Universal Blue key. Already enrolled — not the cause.
3. **Apply zbowling/mt7925 DKMS patches** — Community patchset fixing 7 mt7925e bugs (NULL derefs, race conditions, deadlocks). These patches (v7, Jan 2026) have NOT been merged into mainline or the OGC `6.19.14-ogc2.1` kernel. Reserved as contingency.
4. **Add `disable_aspm=1` module parameter** — Common workaround for mt7925e init failures. Not needed.

## Rationale
The simplest fix is to unmask iwd, which the base image (`bazzite:stable`) ships as masked. NetworkManager is configured with `wifi.backend=iwd`, creating a contradiction that prevents the WiFi daemon from starting.

## Requirements
- WiFi must work on the custom image without manual intervention
- Must survive `bootc rebase` and reboot
- No kernel or module changes

## Root Cause
`bazzite:stable` masks `iwd.service` by shipping symlinks to `/dev/null` at:
- `/etc/systemd/system/iwd.service`
- `/usr/etc/systemd/system/iwd.service`

Meanwhile, NetworkManager is configured with:
```
cat /etc/NetworkManager/conf.d/iwd.conf
[device]
wifi.backend=iwd
wifi.iwd.autoconnect=yes
```

This contradiction means: NetworkManager sees the WiFi device (`wlp192s0`), loads the plugin, but can never make it available because the iwd backend never starts — the interface stays stuck in `unavailable`.

## Technical Approach
1. Remove the mask symlinks from both `/etc/systemd/system/` and `/usr/etc/systemd/system/` during image build
2. Enable iwd so it starts at boot
3. NetworkManager (with `wifi.backend=iwd`) can then manage the interface

## Debug Log
1. Booted custom image → no WiFi networks visible
2. `dmesg` showed mt7925e module loads fine, firmware loads, `wlp192s0` created
3. `lsmod` confirmed mt7925e loaded
4. `nmcli dev status` showed `wlp192s0 wifi unavailable`
5. `systemctl status iwd` → `masked`
6. `systemctl unmask iwd && systemctl start iwd` → WiFi instantly works
7. `find /usr/etc/systemd/system/ -lname '/dev/null'` confirmed mask source
8. Confirmed NetworkManager `wifi.backend=iwd` config

## Files Affected
- **Modified**: `build_files/build.sh` — add rm of mask files and `systemctl enable iwd` before `systemctl enable libvirtd`

## Issues & Resolutions

### Issue 1: Mask in /etc/ also blocks enable
- **Problem**: `rm -f /usr/etc/systemd/system/iwd.service` followed by `systemctl enable iwd` fails because the mask also exists at `/etc/systemd/system/iwd.service`. `systemctl enable` refuses to enable a masked unit.
- **Resolution**: Remove from **both** `/etc/systemd/system/iwd.service` and `/usr/etc/systemd/system/iwd.service` before enabling.
