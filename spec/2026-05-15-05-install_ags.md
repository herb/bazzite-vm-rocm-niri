# Install AGS (Aylur's GTK Shell) — multi-stage build + Astal from COPR

## Context

The custom Bazzite image adds Niri as an alternative window manager. AGS
provides a customizable widget shell (bars, notifications, app launchers)
making the Niri desktop more functional and visually polished.

AGS is not available in the main Fedora repos. It requires two components:
1. The **Astal** runtime libraries (GJS GTK bindings — `astal-gjs`, `astal-libs`, `astal-gtk4`)
2. The **AGS** binary + JS data (`/usr/bin/ags` + `/usr/local/share/ags/`)

## Discovery: Fedora 44 incompatibility

The base image `ghcr.io/ublue-os/bazzite:stable` tracks Fedora 44.

- `solopasha/hyprland` COPR has `aylurs-gtk-shell2` but only up to Fedora 43
- `aneagle/ags-3` COPR supports Fedora 44 but only has Astal packages, not AGS itself

Therefore a **hybrid approach** is required: Astal from COPR RPMs, AGS binary
built from source in a multi-stage build.

## Alternatives considered

| Approach | Reason rejected |
|----------|----------------|
| COPR-only (`solopasha/hyprland`) | No Fedora 44 support |
| COPR-only (`aneagle/ags-3`) | No AGS package, only Astal |
| Build everything from source inline | Build deps bloat final image |
| Astal from source + AGS from source | Unnecessary — Astal has working RPMs |

## Rationale

- Astal libraries are complex C+Vala+introspection builds; getting them as
  RPMs avoids compilation complexity.
- The AGS binary is a single Go program with JS data files — simple to build
  from source in a dedicated stage.
- Multi-stage build keeps golang, npm, meson, etc. out of the final image.

## Requirements

- AGS binary (`/usr/bin/ags`) is installed in the image.
- Astal runtime libraries are installed from the `aneagle/ags-3` COPR.
- A systemd user service is available for AGS (not auto-enabled).
- No build deps (golang, npm, meson) leak into the final image.
- The image builds successfully.

## Technical approach

### Multi-stage Containerfile

**Build stage** (`ags-builder`, `Containerfile:16-33`):
- Same base image (`bazzite:stable`)
- Install only what's needed to compile AGS: `golang`, `npm`, `meson`,
  `ninja-build`, `gjs`, `gtk4-layer-shell-devel`, `git-core`
- Clone `https://github.com/aylur/ags.git`, run `npm install`, `meson setup build`,
  `meson install -C build`
- Installs to `/usr/local/` (default meson prefix)

**Final stage** (`Containerfile:38-78`):
- Copies `/usr/local/` from build stage — gives us:
  - `/usr/local/bin/ags` (Go binary)
  - `/usr/local/share/ags/js/` (JS/TypeScript config loader modules)
- Then runs `build.sh` as before

### build.sh changes (`build_files/build.sh:67-73`)

```bash
dnf5 -y copr enable aneagle/ags-3
dnf5 install -y astal-gjs astal-libs astal-gtk4
```

- `dnf5 -y copr enable` with `-y` avoids interactive prompt (the original CI
  failure was caused by missing `-y` flag, which caused the COPR to not be
  enabled when running non-interactively in buildah).

### Service file (`services/ags.service`)

Standard systemd user unit:
- `ExecStart=/usr/bin/ags`
- `WantedBy=niri.service` — user enables manually with `systemctl --user enable ags.service`
- NOT auto-enabled (no `add-wants` call in build.sh) since AGS requires a
  per-user config at `~/.config/ags/`.

## Files affected

- `Containerfile` — added `ags-builder` build stage, added `COPY --from=ags-builder`
- `build_files/build.sh` — replaced `solopasha/hyprland` COPR + `aylurs-gtk-shell2`
  with `aneagle/ags-3` COPR + Astal runtime packages
- `services/ags.service` — new systemd user unit (unchanged from original plan)
- `spec/2026-05-15-05-install_ags.md` — this PRD

## End criteria

- ✅ AGS binary + JS data built from source in ags-builder stage
- ✅ Astal runtime libraries (astal-io, astal-gtk4) built from source in same stage
- ✅ Astal GJS TypeScript types built from source in same stage
- ✅ No build deps in final image (vala, golang, npm, meson only in build stage)
- ✅ Systemd user service available but not auto-enabled
- ✅ Image builds and passes `bootc container lint`

## Issues & Resolutions

| Issue | Resolution |
|-------|-----------|
| `solopasha/hyprland` COPR only supports up to Fedora 43; `bazzite:stable` is Fedora 44 | Switched to `aneagle/ags-3` COPR for Astal, multi-stage for AGS binary |
| `aneagle/ags-3` COPR Astal packages built for Fedora 43, missing `libappmenu-glib-translator.so.0` on Fedora 44 | Abandoned all COPRs; build both Astal and AGS from source in multi-stage build |
| `dnf5 copr enable` prompts interactively without `-y`, causing CI failure | Would have needed `-y` flag, but moot since we removed all COPR usage |
| AGS has no upstream systemd user service to reference | Created one following the pattern of existing `services/swayidle.service` and `services/plasma-polkit-agent.service` |
| `/root` is a dangling symlink to `/var/roothome` in bootc images, breaking npm + Go | Set `HOME=/tmp GOCACHE=/tmp/go-cache GOPATH=/tmp/go` for all npm/go commands |
| `/usr/local` is a dangling symlink to `/var/usrlocal` in bootc images, breaking meson install | Added `mkdir -p /var/usrlocal` before meson install |

## Build artifacts

Verified in final image:
- `/usr/local/bin/ags` — 16 MB Go binary
- `/usr/local/lib64/libastal-4.so*` — Astal GTK4 library
- `/usr/local/lib64/libastal-io.so*` — Astal IO library
- `/usr/local/lib64/girepository-1.0/Astal-4.0.typelib` — GObject Introspection typelib
- `/usr/local/share/ags/js/` — AGS TypeScript module loader + node_modules
- `/usr/local/share/astal/gjs/` — Astal GJS type definitions
